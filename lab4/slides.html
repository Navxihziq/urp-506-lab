The Normal Distribution

What is a normal distribution?

A continuous probability distribution that is:

  • Bell-shaped and symmetric around its center
  • Fully described by two parameters: mean \(\mu\) (center) and standard deviation \(\sigma\) (spread)
  • Mean = median = mode

We write \(X \sim N(\mu, \sigma^2)\).

The standard normal is the special case \(\mu = 0\), \(\sigma = 1\): \(Z \sim N(0, 1)\).

Same shape, different \(\mu\) and \(\sigma\)

\(\mu\) shifts the curve left or right. \(\sigma\) stretches or squeezes it. Total area is always 1.

Z-scores: any normal to the standard normal

\[ z = \frac{x - \mu}{\sigma} \]

How many standard deviations \(x\) sits from the mean.

If \(X \sim N(\mu, \sigma^2)\), then \(Z = \frac{X - \mu}{\sigma} \sim N(0, 1)\).

Example. Commute times \(\sim N(20, 10^2)\). A 28-minute commute:

\[ z = \frac{28 - 20}{10} = 0.8 \]

We just saw normals with different means and spreads. A z-score puts all of them on one ruler: subtract the mean, divide by the standard deviation. The answer is in units of standard deviations. Commute times with mean 20 and sd 10: a 28-minute commute is 0.8 standard deviations above average. Two payoffs. First, once you’re in z units, the standard normal, the one with default arguments in R, answers the question for any normal. Second, you can compare things measured in different units, like a county’s income and its population, because both become “how unusual is this.” Watch for this exact example in practice question 1.

Same curve, two rulers

Figure 1

Same curve, two axes. Minutes on the bottom, z on the top. The dashed line is the mean: 20 minutes, z = 0. Every 10 minutes is one step in z. 28 minutes lines up with 0.8 on the top axis. Standardizing doesn’t change the shape; it only relabels the axis. If anyone notices the curve extending below zero minutes: this model assigns about 2% probability to negative commutes, a reminder that the normal is an approximation.

Probability density function (PDF)

\[ f(x) = \frac{1}{\sigma\sqrt{2\pi}} \, e^{-\frac{(x-\mu)^2}{2\sigma^2}} \]

The height of the curve at \(x\).

Density is not probability. For a continuous variable P(X = 1) = 0; probabilities come from areas.

Cumulative distribution function (CDF)

\[ F(x) = P(X \le x) = \int_{-\infty}^{x} f(t)\,dt \]

The area under the PDF up to \(x\).

The CDF as a curve

Plot \(F(x)\) for every \(x\) and you get an S-curve running from 0 to 1.

Reading it backwards: quartiles

Fix the area, solve for \(x\). The values that cut the curve into four 25% slices are the quartiles.

Normal Distribution Functions in R

dnorm(), pnorm(), qnorm(), rnorm()

Function Stands for Question it answers Returns
dnorm(x) density How tall is the curve at \(x\)? \(f(x)\), the PDF
pnorm(q) probability What share falls at or below \(q\)? \(F(q) = P(X \le q)\), the CDF
qnorm(p) quantile Which \(x\) has \(p\) of the area below it? \(F^{-1}(p)\), the inverse CDF
rnorm(n) random Give me \(n\) draws from this distribution \(n\) simulated values

All four take mean and sd (defaults: mean = 0, sd = 1).

The same prefixes work for other distributions: dbinom(), pt(), qchisq(), …

Same curve, four functions

dnorm(1)        # height at x = 1
[1] 0.2419707
pnorm(1)        # area left of x = 1
[1] 0.8413447
qnorm(0.75)     # x with 75% below it (Q3)
[1] 0.6744898
set.seed(42)
rnorm(5)        # five random draws
[1]  1.3709584 -0.5646982  0.3631284  0.6328626  0.4042683

Graphing in R

Goal: see the distribution

Figure 2

This is where we’re headed. Bars are 1,000 random draws from rnorm. The line is dnorm, the PDF from earlier. If the draws really come from this distribution, the bars should hug the curve. We’ll build this exact figure twice, once in base R and once in ggplot2, so the only thing that changes is syntax.

Step 0: simulate the data

set.seed(506)
draws <- data.frame(value = rnorm(1000, mean = 0, sd = 1))
head(draws, 3)
       value
1  0.2365663
2 -1.7974184
3  1.1618584

set.seed makes the random draws reproducible. Same seed, same numbers, on everyone’s machine. rnorm with n = 1000, mean 0, sd 1 gives us the standard normal. We wrap it in a data frame because ggplot wants a data frame; base R is happy with a vector, but this way both use the same object. One column, called value.

Base R: the template

hist(<VECTOR>, freq = FALSE, breaks = <N>,
     main = "<title>", xlab = "<x label>", ylab = "<y label>")

curve(<FUNCTION>(x), add = TRUE, <STYLE>)
  • hist(): draws a histogram of a numeric vector; freq = FALSE puts it on the density scale
  • curve(): draws a function of x across the plot
  • add = TRUE: draw on the current plot instead of starting a new one

Two functions, two jobs. hist takes a numeric vector, not a data frame, so we’ll pass it a column with the dollar sign. freq = FALSE puts it on the density scale. breaks, main, and the axis labels are optional; the defaults work, they’re just ugly. curve takes an expression in x, and it has to be literally the letter x, which curve fills in across the plot’s range. add = TRUE is the key argument; leave it off and curve wipes the histogram and draws on a fresh canvas. Style arguments like lwd for line width and col for colour come last. Next slide, same template with our data plugged in.

Base R: draw, then add

hist(draws$value, freq = FALSE, breaks = 30,
     main = "1,000 draws from N(0, 1)", xlab = "x", ylab = "Density")
curve(dnorm(x), add = TRUE, lwd = 2, col = "navy")

Figure 3

Two function calls. hist draws the histogram right away. freq = FALSE switches the y axis from counts to density; without it the bars go up to around 100 and the curve would be a flat line at the bottom. breaks sets roughly how many bars. Then curve draws dnorm on top, and add = TRUE is what stops it from opening a new plot. That’s the base R logic: every call paints on the current canvas immediately, in order.

ggplot2: describe, then render

ggplot(data = <DATA>, mapping = aes(<MAPPINGS>)) +
  <GEOM_FUNCTION>() +
  <GEOM_FUNCTION>()
  • data: a data frame
  • aes(): which columns map to x, y, color, …
  • geom: how to draw them (bars, lines, points, …)

ggplot works differently. You describe the plot: here is the data, here is which column goes on which axis, here is the shape to draw. Layers are joined with a plus sign. Nothing appears until the whole object is printed. Every ggplot you’ll ever write fits this template. Let’s fill it in one line at a time.

Build it: data + mapping

ggplot(draws, aes(x = value))

Data is draws, and we map the value column to x. We get a canvas with an x axis already scaled to the data, but nothing on it, because we haven’t said how to draw anything yet. That’s a geom’s job.

Build it: add a histogram

ggplot(draws, aes(x = value)) +
  geom_histogram(aes(y = after_stat(density)), bins = 30)

geom_histogram draws the bars. after_stat(density) means: after counting, put density on the y axis instead of the count. It’s the ggplot equivalent of freq = FALSE, and we need it for the same reason: so the curve fits. bins plays the role of breaks.

Build it: add the PDF

ggplot(draws, aes(x = value)) +
  geom_histogram(aes(y = after_stat(density)), bins = 30) +
  geom_function(fun = dnorm)

geom_function draws any function across the x range. We pass dnorm, the same dnorm we called earlier by hand. Plus sign, new layer. Compare with base R: there it was curve with add = TRUE; here, adding is simply what the plus sign does.

Build it: labels and style

ggplot(draws, aes(x = value)) +
  geom_histogram(aes(y = after_stat(density)), bins = 30,
                 fill = "#4dd8c8", colour = "white") +
  geom_function(fun = dnorm, linewidth = 1.2) +
  labs(title = "1,000 draws from N(0, 1)",
       x = "x", y = "Density") +
  theme_classic()

Nothing new structurally, just polish. Click through the highlights. fill and colour on the histogram: fill is the inside of the bars, colour is the outline. Note that these are outside aes because they are fixed values, not mapped from data. linewidth thickens the curve. labs sets the title and axis labels. theme_classic strips the grey background. Same figure as the base R version.

Where aes() goes

In ggplot(): every layer inherits it

ggplot(draws, aes(x = value)) +
  geom_histogram(bins = 30) +
  geom_boxplot()

In a geom: that layer only

ggplot(draws) +
  geom_histogram(aes(x = value),
                 bins = 30)

Rule of thumb: put a mapping in ggplot() if every layer uses it; put it in the geom if only one does.

A common point of confusion. A mapping inside ggplot() is shared by every layer below it. A mapping inside a geom applies to that geom only. On the left, both the histogram and the box plot get x = value. On the right, only the histogram knows about it. geom_function, which we just used, needs no mapping at all; it computes its own y from fun.

Before the box plot, find the quartiles directly. quantile() takes the data and the probabilities we want: 25, 50, 75 percent. It returns about -0.68, 0.03, and 0.73. Compare with qnorm(c(0.25, 0.5, 0.75)): -0.67, 0, 0.67. Close, not identical. quantile() works on the sample, qnorm() on the theoretical distribution; with 1,000 draws they nearly agree. abline with v = draws vertical lines at those values, one per quartile, on top of the existing histogram, the same draw-then-add logic as curve. In ggplot the equivalent is geom_vline(xintercept = q). Keep these three lines in mind: the next slide draws them as a box.

Box plot: the quartile slide, redrawn

boxplot(draws$value, horizontal = TRUE, xlab = "x")
ggplot(draws, aes(x = value)) +
  geom_boxplot() +
  theme_classic()

Same data, one line in base R, three in ggplot. The box runs from Q1 to Q3, and the line inside is Q2, the median. This is the quartile slide from earlier, flattened onto one axis. Check it: the box edges should sit near qnorm(0.25) and qnorm(0.75), about minus and plus 0.67. The whiskers extend to the most extreme point within 1.5 times the box width; dots beyond that are drawn individually. For a normal, expect a handful of those, which doesn’t mean anything is wrong. The y axis on the ggplot version is meaningless; ignore it.

Box plots: comparing groups (base R)

draws2 <- data.frame(value = rnorm(1000, mean = 1, sd = 2))

boxplot(draws$value, draws2$value,
        names = c("draws", "draws2"),
        horizontal = TRUE, xlab = "x")

Figure 4

First, one more sample: 1,000 draws from a normal with mean 1 and sd 2. Base R’s boxplot takes as many vectors as you like, one box per vector; names labels them. Reading a box: it runs from Q1 to Q3, the line inside is Q2, the median. That’s the quartile slide from earlier, flattened onto one axis. For draws, the box edges sit near plus and minus 0.67, same as qnorm. Whiskers reach the most extreme point within 1.5 box-widths; dots beyond are drawn individually. For a normal, expect a handful, which doesn’t mean anything is wrong. Now compare: draws2 is shifted right, that’s the mean of 1, and its box is about twice as wide, that’s the sd of 2. This is what box plots are for: comparing distributions side by side.

Box plots: comparing groups (ggplot2)

both <- data.frame(
  group = rep(c("draws", "draws2"), each = 1000),
  value = c(draws$value, draws2$value)
)

ggplot(both, aes(x = value, y = group)) +
  geom_boxplot() +
  theme_classic()

Figure 5

ggplot works differently. It wants one data frame, with one column for the values and one column saying which group each value belongs to. So we stack the two samples: rep repeats each label 1,000 times, and c concatenates the values in the same order. This is called long format. Then group goes to y, and ggplot draws one box per group automatically. Practice question 3 needs exactly this, with real variables instead of draws. In the tidyverse, pivot_longer does the stacking for you; the handout shows it.
